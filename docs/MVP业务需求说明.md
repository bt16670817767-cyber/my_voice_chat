# SimpleVoiceChat MVP业务需求说明

## 1. 文档目的
本说明用于定义 SimpleVoiceChat 第一阶段（MVP）的业务目标、范围、核心需求和验收标准，确保项目可在最短路径完成可演示闭环。

## 2. 项目定位
- **定位**：技术演示/学习项目
- **本阶段目标**：快速产出可运行、可演示的端到端语音聊天闭环
- **不追求**：商业化后台能力（计费、复杂权限体系、运营系统、风控体系）

## 3. 目标用户与使用场景
### 3.1 目标用户
- 学习实时音频通信的开发者
- 需要展示基础语音通信链路的演示者

### 3.2 核心场景
- **场景A：本地单机联调**
  - 使用 Docker 启动服务端
  - 在 Windows 上运行客户端
  - 验证连接、开关音频和状态显示
- **场景B：双端语音演示**
  - 两个客户端加入同一频道
  - 验证双向语音收发
- **场景C：基础异常恢复**
  - 服务端未启动/端口错误时给出清晰反馈
  - 中断后允许用户重新连接并恢复操作

## 4. 业务目标与成功标准
### 4.1 业务目标
- 用最少功能证明“可连接 + 可通话 + 可观测”的完整链路。
- 让演示人员在 5 分钟内完成一次标准演示流程。

### 4.2 成功标准（MVP）
- 演示脚本一次通过率 >= 90%（同一机器/同一网络环境下重复执行）
- 首次启动到完成通话演示耗时 <= 5 分钟
- 核心状态可视化可覆盖连接状态、音频状态、服务端收发统计

## 5. 功能需求分层
## 5.1 P0（必须实现）
1. **基础连接**
   - 用户可输入 Server IP / Port / Channel。
   - 点击 Connect 后可建立连接；失败时展示可理解错误状态。
2. **音频控制**
   - 用户可执行 Start Audio / Stop Audio。
   - UI 状态与真实音频状态一致，不允许“显示已开启但实际未采集/发送”。
3. **基础通话**
   - 至少两个客户端在同一频道可进行基本语音收发。
4. **运行可视**
   - 客户端展示连接状态与音频状态。
   - 服务端展示运行状态、端口和收发统计数据。

## 5.2 P1（后置增强）
1. 最近一次连接参数持久化
2. 自动重连与弱网提示
3. 简单质量指标展示（如丢包估计、延迟估计）

## 6. 非功能需求（最低门槛）
1. **稳定性**
   - 连续 10 分钟通话过程中不出现崩溃。
2. **可用性**
   - 核心操作控制在 3 步内：连接 -> 开启音频 -> 停止音频。
3. **可观测性**
   - 关键状态变化在客户端或服务端可见，便于排障演示。
4. **环境约束说明**
   - 明确当前支持的最小演示环境：Windows 客户端 + Docker 服务端。

## 7. 验收口径
### 7.1 功能验收
- 每条 P0 需求必须提供可重复步骤与预期结果。
- 验收结果应标记为“通过/失败/阻塞”。

### 7.2 失败路径验收
- 服务端未启动时连接失败提示正确。
- 错误端口输入时连接失败提示正确。
- 重复点击 Start/Stop 不导致状态错乱或崩溃。

## 8. 风险与控制
1. **音频设备差异风险**
   - 通过“支持环境基线”限制 MVP 演示范围。
2. **网络与端口风险**
   - 在文档中固定演示端口和启动顺序。
3. **范围膨胀风险**
   - 严格执行 P0 冻结，P1 不插入当前里程碑。
