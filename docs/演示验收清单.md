# SimpleVoiceChat 演示验收清单

## 1. 目的
本清单用于验证 MVP 的 P0 需求是否可重复通过，支持演示前快速自检与问题定位。

## 2. 验收环境
- 操作系统：Windows 10/11（客户端）
- 服务端：Docker 容器运行 VoiceChatServer
- 网络：客户端可访问服务端 UDP 端口（默认 27020）
- 音频设备：至少 1 个可用输入设备和输出设备

## 3. 标准演示脚本（主链路）
### Step 1 - 启动服务端
- 操作：
  - 在项目根目录执行服务端启动命令（参考 `TODAY_SETUP_SUMMARY_2026-04-23.md`）
- 预期结果：
  - 服务端 UI 正常显示运行状态与端口
  - 无崩溃、无异常退出
- 记录项：
  - 结果：通过/失败/阻塞
  - 备注：异常日志或截图

### Step 2 - 启动客户端A与客户端B
- 操作：
  - 分别启动两个客户端实例
  - 设置相同 Server IP / Port / Channel
- 预期结果：
  - 两个客户端窗口均可正常打开
  - 参数输入可编辑，UI控件响应正常
- 记录项：
  - 结果：通过/失败/阻塞
  - 备注：窗口异常或输入异常

### Step 3 - 建立连接
- 操作：
  - 在两个客户端分别点击 Connect
- 预期结果：
  - 客户端连接状态变为已连接（或等效状态）
  - 服务端有连接相关状态变化或统计变化
- 记录项：
  - 结果：通过/失败/阻塞
  - 备注：失败提示是否可理解

### Step 4 - 开启音频并双向通话
- 操作：
  - 客户端A、B分别点击 Start Audio
  - 双方交替讲话 30 秒
- 预期结果：
  - 双方都可听到对方声音
  - 客户端音频状态显示正确
  - 服务端收发统计有持续变化
- 记录项：
  - 结果：通过/失败/阻塞
  - 备注：音质、断续、明显延迟体感

### Step 5 - 停止音频并退出
- 操作：
  - 两端点击 Stop Audio
  - 关闭客户端，退出服务端
- 预期结果：
  - 状态正确切换为停止
  - 退出过程无崩溃
- 记录项：
  - 结果：通过/失败/阻塞
  - 备注：退出时是否出现卡死

## 4. 失败路径验收
### Case F1 - 服务端未启动
- 操作：不启动服务端，直接在客户端点击 Connect
- 预期结果：客户端连接失败且有可理解提示，不崩溃

### Case F2 - 端口错误
- 操作：客户端填写错误端口后点击 Connect
- 预期结果：连接失败提示明确，不进入“伪连接成功”状态

### Case F3 - 重复点击 Start Audio
- 操作：已开启音频后再次点击 Start Audio
- 预期结果：不崩溃，状态不紊乱

### Case F4 - 重复点击 Stop Audio
- 操作：已停止音频后再次点击 Stop Audio
- 预期结果：不崩溃，状态保持可预期

## 5. 通过准则
- 主链路 Step 1~5 全部“通过”
- 失败路径 F1~F4 不出现崩溃，且提示/状态符合预期
- 若存在“阻塞”项，需标记原因并回退到实现阶段处理
